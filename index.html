01. Foundations of Prompt Engineering

Prompt engineering is the empirical science of structuring instructions, context, and constraints so that Large Language Models produce accurate, deterministic, and safe outputs. Instead of treating an LLM like a search engine, effective engineers program it through natural language structure.

🎯 Anatomy of a Great Prompt

Every robust prompt combines 5 pillars: Persona (Role), Task Directive, Contextual Knowledge, Constraints/Guardrails, and explicit Output Formatting (e.g., JSON or Markdown table).

🧠 Zero-Shot vs Few-Shot

Zero-shot relies purely on pre-trained weights. Few-shot (In-Context Learning) provides 2–5 input/output pairs inside the prompt to anchor style, edge cases, and label syntax.

🔗 Chain-of-Thought (CoT)

By instructing the model to "think step-by-step" before stating its final verdict, you allocate extra generation tokens for intermediate reasoning, drastically boosting math and logic accuracy.

02-understanding-llms.md

02. Understanding LLMs: Tokens, Attention & Sampling

Large Language Models are autoregressive Transformer neural networks. They do not think or look up facts in a database; instead, they break text into sub-word units called tokens, compute contextual relationships via Self-Attention, and predict a probability distribution over the entire vocabulary for the very next token.

🧩 Byte-Pair Tokenization

Text is split into tokens (~4 characters or 0.75 words per token in English). Rare words and non-English characters often consume multiple tokens, directly impacting context limits and API billing.

🔍 Self-Attention Mechanism

Every token attends to every preceding token via Query, Key, and Value vectors, allowing the model to resolve pronouns, track long-range code dependencies, and weigh relevant context.

🎲 Temperature & Top-p

Temperature scales logits before the Softmax function. Low T (0.0) makes the highest-probability token dominate; high T (>1.0) flattens the curve, encouraging creative or hallucinated choices.

03. Chat Models, Roles & Conversational Memory

While base models simply complete documents, Chat Models are post-trained with Supervised Fine-Tuning (SFT) and Reinforcement Learning from Human Feedback (RLHF). They process structured arrays of role-tagged messages (`system`, `user`, `assistant`) and rely on the developer resending prior turns to maintain the illusion of memory.

🛡️ The System Role

Sets global behavioral instructions, tone, forbidden topics, and output constraints with higher authority than regular user messages.

🔄 Stateless Memory Illusion

LLM APIs do not remember past calls automatically. Every turn requires sending the entire conversation history (or a summarized sliding window) inside the payload.

🧱 Guardrails & Injection Defense

Malicious users attempt "Ignore previous instructions" attacks. Separating untrusted user input and reinforcing system boundaries prevents role hijacking.

04-designing-llm-applications.md

04. Designing Production LLM Applications

Integrating a probabilistic language model into deterministic software requires strong architectural patterns: structured schema enforcement, multi-step prompt chaining, semantic caching, and intelligent model routing to balance cost, latency, and intelligence.

📐 Structured Outputs & Tools

Force the LLM to adhere to strict JSON Schemas or invoke external APIs (Function Calling) so downstream code never crashes on unexpected conversational prose.

⛓️ Prompt Chaining & Routing

Break complex workflows into sequential specialized prompts (Classify -> Retrieve -> Draft -> Verify) rather than cramming everything into one brittle mega-prompt.

⚡ Latency & Cost Optimization

Use small fast models (8B) for classification and routing, reserving frontier reasoning models only for complex synthesis, backed by prompt caching.

05. Prompts, Context Engineering & RAG Pipelines

Retrieval-Augmented Generation (RAG) grounds LLMs in private or up-to-date facts without expensive weight fine-tuning. Documents are split into chunks, converted into high-dimensional vectors via an embedding model, retrieved via Cosine Similarity, and injected directly into the prompt context.

🧭 Vector Embeddings

Transforms sentences into numerical coordinate arrays (e.g., 1536 dimensions) where semantically similar concepts cluster closely together regardless of exact keyword overlap.

✂️ Chunking & Overlap

Splitting PDFs or Markdown files into 256–512 token chunks with 10–20% sliding overlap preserves semantic focus while preventing mid-sentence context loss.

🏆 Hybrid Search & Reranking

Combining dense vector similarity with sparse keyword search (BM25) and a Cross-Encoder Reranker maximizes retrieval precision and prevents "Lost in the Middle" degradation.
